# 自動交易程式

依 `docs/strategy.md` 的規則，在幣安現貨帳戶自動執行：兩本帳（A 帳週日、B 帳週四）調倉、每日出場、
40% 波動縮放、閒置 USDT 放活期理財。

只用 Python 標準函式庫加 `pandas`、`numpy`，不需要其他套件。

## 檔案

| 檔案 | 用途 |
|---|---|
| `run.py` | 主程式，每天執行一次 |
| `engine.py` | 策略邏輯：訊號（直接呼叫 `tools/factor_research.py`）、兩本帳、訂單規劃 |
| `brokers.py` | 下單執行：紙上交易（模擬）／實盤 |
| `binance_api.py` | 幣安 API 最小封裝 |
| `replay.py` | 歷史重播：用歷史資料逐日跑 `run.py` 的流程，檢查與回測是否一致 |
| `state_<模式>.json` | 執行狀態（兩本帳的持倉、淨值紀錄），自動產生；`--backup-dir` 可自動備份 |
| `logs/` | 每日執行紀錄 |

## 三種模式

| 模式 | 需要 API key | 下單 | 存狀態 | 用途 |
|---|---|---|---|---|
| `paper` | 否 | 否（以收盤價模擬） | 是 | 先跑幾週，熟悉每天的輸出 |
| `dry` | 是（唯讀即可） | 否，只印出訂單 | 否 | 上線前確認 API 連線、餘額讀取正常 |
| `live` | 是 | **是** | 是 | 實盤 |

```bash
# 紙上交易（第一次要給初始資金）
python bot/run.py --mode paper --capital 10000

# 演練與實盤：API key 用環境變數提供，不要寫進程式或檔案
export BINANCE_API_KEY=...
export BINANCE_API_SECRET=...
python bot/run.py --mode dry  --capital 1000
python bot/run.py --mode live --capital 1000
```

`--capital` 只在第一次（沒有狀態檔時）使用，代表交給策略管理的 USDT。
帳戶裡多出來的 USDT 和其他資產不會被動用。

## 每天什麼時候執行

幣安日 K 在 **UTC 00:00（台灣時間 08:00）** 收盤。請在 **UTC 00:05 左右** 執行：

- 每天：檢查持倉，跌破均線的幣賣出（新倉 20 日、舊倉 40 日均線）
- 週一 08:05（台灣）：處理週日收盤 → **A 帳調倉**
- 週五 08:05（台灣）：處理週四收盤 → **B 帳調倉**

驗證顯示收盤後 6 小時內（台灣 14:00 前）執行影響不大，超過 8 小時開始變差，延遲一天明顯變差（`docs/validation.md` 1.1）。萬一漏跑，當天中午前手動補跑即可。同一根日 K 只會處理一次，
不小心重複執行不會重複下單。

### 排程範例

Linux / macOS（crontab，主機時區為 UTC 時）：

```
5 0 * * * cd /path/to/123 && BINANCE_API_KEY=... BINANCE_API_SECRET=... /usr/bin/python3 bot/run.py --mode live >> bot/logs/cron.log 2>&1
```

Windows：工作排程器，每天台灣時間 08:05 執行
`python C:\path\to\123\bot\run.py --mode live`（API key 設為使用者環境變數）。建議設定：

| 分頁 | 設定 | 用途 |
|---|---|---|
| 一般 | 不論使用者登入與否均執行 | 開機後不用登入也會跑 |
| 設定 | 錯過排定的啟動時間後，盡快執行工作 | 08:05 沒開機，之後一開機就自動補跑 |
| 設定 | 如果工作失敗，重新啟動間隔 5 分鐘、嘗試 3 次 | 剛開機網路還沒連上時自動重試 |
| 條件 | 取消「只在使用 AC 電源時才啟動」（筆電） | 用電池時也會跑 |

收盤後 6 小時內（台灣 14:00 前）補跑影響很小。**整天沒執行**時，當天該做的調倉會跳過到下週，
每日出場則隔天照常檢查。

家用網路的 IP 可能會變。變了之後幣安會拒絕連線，紀錄會出現錯誤，到幣安 API 管理更新白名單即可；
建議每週看一次紀錄。

## 幣安帳戶設定

1. **API 管理** 建立 API key，權限只勾選：
   - 啟用讀取
   - 啟用現貨及槓桿交易
   - **不要**勾選提幣
2. 設定 **IP 白名單**，只允許執行程式的那台機器。
3. 執行環境必須能連到幣安：台灣本機或東京、新加坡的 VPS。
   美國的主機（包含 Google Colab）通常會被幣安封鎖。
4. 帳戶內準備至少 `--capital` 的 USDT（現貨或活期皆可）。
   資金太小時每筆訂單會低於最低下單金額（約 5 USDT），建議至少 500 USDT。

## 安全機制

- **緊急停止**：在 `bot/` 建立一個名為 `STOP` 的空檔案，程式就不會執行任何動作。刪掉即恢復。
- **不重複下單**：下單請求遇到網路錯誤時不會自動重送（可能其實已成交），隔天執行時會先對帳。
- **對帳**：實盤每次執行前，用實際餘額修正帳本（活期利息、以幣扣的手續費）。
  如果發現帳戶 USDT 比上次少很多，會在紀錄中警告。
- **零頭**：低於最低下單金額、賣不掉的零頭會從帳本移除，記錄在 `state` 的 `dust`。

## 電腦故障備案

**平常就做好：**

1. **自動備份狀態**：排程指令加上 `--backup-dir`，指向 OneDrive 或 Google 雲端硬碟的資料夾，例如
   `python bot\run.py --mode live --backup-dir "C:\Users\你\OneDrive\bot_backup"`
   （也可以設環境變數 `BOT_BACKUP_DIR`）。每次執行後會複製最新的狀態檔、當天紀錄，
   並在 `history/` 保留最近 90 天的狀態檔。
2. **備用機器**：另一台電腦（例如筆電）先裝好 Python、下載程式、跑過 `python bot/test_bot.py`，
   但**不要設排程**。
3. API key **不要**放進備份資料夾。

**電腦壞掉時：**

| 狀況 | 處理 |
|---|---|
| 1～2 天內修得好 | 不用處理。持倉照留，修好後程式照常執行（期間的出場會延後、調倉可能跳過一次） |
| 超過 2～3 天 | 換到備用機：① 從備份資料夾把 `state_live.json` 複製到 `bot/` ② 幣安 API 管理把白名單改成備用機的 IP ③ 先跑 `--mode dry` 確認 ④ 設好排程 |
| 暫時沒有任何電腦、行情劇烈 | 用幣安 App 手動把策略的幣全部賣成 USDT。恢復後刪掉 `state_live.json`，用 `--capital <目前 USDT>` 重新開始 |
| 狀態檔遺失又沒有備份 | 同上：全部賣成 USDT 後用 `--capital` 重新開始（多付一次手續費，約 0.2%） |
| 電腦遺失或可能中毒 | **立刻到幣安刪除這把 API key**，在新機器上重新建立 |

**同一時間只能有一台機器在跑。** 舊電腦修好後，先停用它的排程，或在它的 `bot/` 放 `STOP` 檔。
兩台都跑會重複下單、帳本也會錯亂。

## 建議的上線步驟

1. `paper` 模式每天跑 2～4 週，確認每週日、週四的調倉與每日出場都合理。
2. `dry` 模式跑幾天，確認 API 連線、餘額讀取、活期查詢正常。
3. `live` 模式先用小額（例如 500～1000 USDT）跑 1～2 個月。
4. 確認實盤紀錄與 `paper` 一致後，再逐步加大資金。

## 歷史重播（檢查程式與回測一致）

```bash
python bot/replay.py --data <download_binance.py 輸出的 data/spot/1d> --start 2023-01-01 --end 2025-12-31
```

會以紙上交易模式，從起始日開始每天執行一次完整流程，輸出淨值序列，可與
`tools/factor_research.py --rebal-days 6,3` 的回測比較。

**已驗證結果（2023-01-01 ～ 2025-12-31，初始 10,000 USDT）：**

| | 年化 | 波動 | 最大回撤 | Calmar | Sharpe |
|---|---|---|---|---|---|
| 重播（本程式逐日執行） | 47% | 33% | -26% | 1.78 | 1.34 |
| 回測（同期間） | 47% | 32% | -26% | 1.78 | 1.34 |

| 年份 | 2023 | 2024 | 2025 |
|---|---|---|---|
| 重播 | +86% | +59% | +8% |
| 回測 | +86% | +55% | +9% |

日報酬相關係數 0.993、週報酬相關係數 0.998，實盤程式的邏輯與回測一致。

## 已知差異與限制

- 實盤以市價單在收盤後幾分鐘成交，價格與回測用的收盤價會有些微差距。
- 波動縮放在各帳自己的調倉日計算並套用；回測是兩帳合併後每週日套用，屬近似，結果略有差異。
- 調倉時，差額小於該帳淨值 0.5% 的部位不調整，以減少手續費。
- 上線前請對照幣安官方 API 文件確認活期理財（Simple Earn）端點，幣安偶爾會調整 API。
