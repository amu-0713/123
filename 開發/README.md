# 開發

原本單檔腳本拆成的可重複執行版本，重點：不重複消耗 finlab API 用量、樣本內/樣本外分開驗證。

## 檔案結構

- `config.py` — 路徑、樣本切分（樣本內 2010–2021 / 樣本外 2022–2026）、所有策略可調參數
- `data_loader.py` — 資料下載＋本地 parquet 快取。**只要 `cache/` 底下檔案齊全就不會再打 API**
- `strategy.py` — 選股/評分邏輯（原腳本的忠實搬移，移除了沒用到的死代碼）。
  支援幾個預設關閉的實驗性開關：`use_adj_price`、`regime_confirm_days`、
  `bear_liq_min_value`、`bear_weight_override`，以及額外的風險因子
  （beta / size / hist_maxdd / margin，權重預設 0）
- `backtest_runner.py` — 包裝 `finlab.backtest.sim`，預設 `upload=False`，只用文字輸出，不上傳、不開網頁圖表
- `main.py` — 正式版入口：抓資料 → 建部位 → 跑樣本內／樣本外回測（**不含任何
  全倉層級的停損/風控 overlay**，測過十幾種都無法穩健改善，見下方章節）
- `experiments.py` — 一次跑過 `config.EXPERIMENTS` 列的變體，拿來做比較測試用
- `risk_overlay.py` — 全倉層級停損 overlay（固定%/ATR、換股/出場/換防禦標的）。
  **最終沒有採用**，程式碼保留給之後想繼續測試用
- `strategy_lowvol.py` — 高息低波策略（你提供的第二個策略）。測過跟主策略
  混合，**最終沒有採用**（樣本內外效果不一致），保留給之後參考
- `stop_loss_individual.py` — 個股停損（觸發後那季空手不遞補）。**最終沒有
  採用**（所有門檻都比不停損還差），保留給之後參考

## 執行方式

```bash
# 第一次執行需要 token（要下載資料），之後有快取就不需要了
export FINLAB_TOKEN="你的token"
python main.py
```

PowerShell：

```powershell
$env:FINLAB_TOKEN = "你的token"
python main.py
```

## 關於「不重複消耗使用量」

`data_loader.load_all_data()` 第一次執行會呼叫 5 次 `data.get()`，抓完整 2006–2026 區間，
存成 `cache/*.parquet`。之後不管跑幾次回測、改幾次參數，都是讀本地檔案，**不會再打 finlab API**。
只有明確呼叫 `load_all_data(force_refresh=True)` 才會重新下載。

## 樣本內 / 樣本外

- 樣本內 2010–2021：用來看策略邏輯、調參數
- 樣本外 2022–2026：只驗證績效是否維持，**不要根據樣本外結果回頭改參數**，
  不然樣本外就失去意義、變相變成樣本內。

## ⚠️ 重要：本地快取一定要包回 FinlabDataFrame

`data.get()` 回傳的不是普通 `pandas.DataFrame`，是 finlab 自己的
`FinlabDataFrame`。它把 `>`、`<`、`==`、`&`、`/` 這些運算子都覆寫過：
兩個 frame 做運算時會自動「取日期聯集 + 前向填補 + 欄位取交集」再運算。

這對這支策略是必要行為——`monthly_revenue` 這種一個月才更新一次的
資料，要靠這個機制才能在非公告日「沿用上一次的值」，跟每日資料
（price、成交金額等）對齊。

`pd.read_parquet()` 讀回來的是「普通」`pandas.DataFrame`，會遺失這個
自動對齊機制，變成標準 pandas 語意（沒有前向填補，NaN 直接讓條件失效），
結果就是營收相關的選股條件在所有季底都是 False，回測整個變成空手。
`data_loader.py` 讀快取時已經用 `FinlabDataFrame(...)` 包回去修正這點，
之後如果要換別的快取方式（例如換成 pickle/feather），記得也要保留這一步。

## 正式版結果（原始策略，不含任何 overlay，2026-09-05 快取版本）

| 指標 | 樣本內 2010–2021 | 樣本外 2022–2026 |
|---|---|---|
| 年化報酬 CAGR | 48.5% | 47.9% |
| **alpha（對 0050）** | **38.3%** | **26.4%** |
| **beta** | **0.90** | **0.75** |
| Sharpe | 1.75 | 1.64 |
| Calmar | 1.72 | 1.61 |
| 最大回撤 | -28.2% | -29.7% |
| 波動度 | 23.5% | 25.5% |
| 勝率 | 61.8% | 57.7% |
| 平均持股數 | 12.1 | 11.4 |
| 策略容量估計 | ~538萬元 | ~739萬元 |

beta 都小於 1（樣本外只有 0.75），扣掉大盤本身的貢獻後還有 26~38% 的
年化 alpha——報酬不是靠放大盤子曝險堆出來的，是真正的選股能力。

## 風控 overlay：測過十幾種，最終決定不加任何一種

一開始曾採用「大盤(0050)回撤15%觸發、留倉換股」，樣本內/外一度同時
改善 Calmar/MaxDD。但為了處理 2025/4 那次跳空崩盤（-28~30% MDD），
後續繼續測試，陸續發現：

| 測過的方向 | 結論 |
|---|---|
| 固定%大盤回撤觸發換股（10%/15%/20%） | 只有15%兩段一致變好，10%/20%樣本內外互相矛盾（像撞到單一事件） |
| ATR 動態門檻（取代固定%） | 全部輸給固定% |
| 停損觸發後空手觀望20天 | 樣本外報酬腰斬，錯過反彈 |
| 熊市邏輯直接換成高息低波（見`strategy_lowvol.py`） | MDD沒改善，報酬大跌（MA regime訊號太慢） |
| 停損觸發換防禦標的、回穩換回成長股 | 來回切換賭時機，比不做還差（OOS MDD -48.7%） |
| 靜態混合高息低波（各種比例） | 樣本外有效、樣本內一致變差，判斷是被單一事件撐出來的 |
| 熊市擴大檔數（5→7→12→16） | 越分散越差，2025 MDD 一路惡化到 -42% |
| 熊市加流動性門檻 | 雙輸或打平 |
| 熊市權重拿掉動能、全押防禦因子 | 雙輸 |
| 熊市加因子：融資使用率/beta/市值/個股歷史最大回撤 | 全部沒能改善 2025 MDD，多數還讓報酬或風險其中一項變差 |
| 個股停損（觸發後那季空手，見`stop_loss_individual.py`） | 所有門檻(10~25%)都比不停損還差，越緊報酬跌越多、MDD還可能更差 |

**根本原因**：查過持股明細後發現，2025/3底切到熊市的5檔持股本身跨5個
不同產業（不是集中度問題），個股跌幅也不算誇張（-3.5%~-20.8%）；問題
是這個策略風格本身（集中持有小型、話題性強的成長/動能股）在真正的
系統性恐慌下，這類股票天生比大型藍籌股/高息股跌得深，這是選股哲學
的固有特徵，不是外掛風控規則能便宜修掉的。最後決定維持原始版本。

如果之後想繼續試，`risk_overlay.py` / `strategy_lowvol.py` /
`stop_loss_individual.py` 的程式碼都還在，可以直接接著用，不用重寫。

## 已知但尚未處理的項目

1. **策略容量偏小**（500~750 萬元量級）：依你實際部署資金規模，可能需要
   重新調整 `liq_min_value`（會犧牲一些 Sharpe/Calmar，是取捨不是免費升級）。
2. 目前的樣本內/樣本外驗證用的是固定切點（2010-2021 / 2022-2026），
   之後如果要繼續調參數，建議改成 rolling walk-forward（每年往前滾動
   重新驗證），比單一固定切點更能防止「試出一個剛好卡準這兩段期間」
   的參數組合。
3. 這次測了很多角度都在選股邏輯「外面」加規則，選股邏輯本身（`final_cond`
   的篩選條件、評分公式）完全沒動過，如果還想繼續優化，那裡可能還有
   空間，只是還沒有方向去查。
